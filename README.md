# Fireflies Clone — Meeting Notes & Transcription Platform

A functional clone of Fireflies.ai's meeting-assistant web app: a meetings
library, an interactive transcript + player view, AI-style summaries/topics,
and full CRUD for meetings and action items.

Real speech-to-text and real LLM calls are out of scope per the assignment —
transcripts are seeded/pasted/uploaded as text, and "AI" summaries/topics/
action items are generated with simple deterministic heuristics (see
`backend/app/utils.py`).

## Tech Stack

- **Frontend:** Next.js 14 (App Router) + TypeScript + Tailwind CSS
- **Backend:** FastAPI (Python) + SQLAlchemy ORM
- **Database:** SQLite (file-based, `backend/fireflies.db`)

## Setup Instructions (Windows / Git Bash)

### 1. Backend

```bash
cd backend
python -m venv venv
source venv/Scripts/activate      # Windows Git Bash
pip install -r requirements.txt
python -m app.seed                # populates 4 sample meetings
uvicorn app.main:app --reload --port 8000
```

Backend now running at `http://localhost:8000`. Interactive API docs at
`http://localhost:8000/docs` (auto-generated by FastAPI).

### 2. Frontend

In a **second terminal**:

```bash
cd frontend
npm install
cp .env.local.example .env.local   # or copy manually on Windows
npm run dev
```

Frontend now running at `http://localhost:3000` — open it in your browser.

## Architecture Overview

```
Fireflies_Clone/
├── backend/
│   └── app/
│       ├── main.py          # FastAPI app, CORS, router registration
│       ├── database.py      # SQLAlchemy engine/session setup
│       ├── models.py        # DB tables (SQLAlchemy ORM classes)
│       ├── schemas.py        # API request/response shapes (Pydantic)
│       ├── utils.py         # transcript parsing + mock "AI" generation
│       ├── seed.py          # populates sample data
│       └── routers/
│           ├── meetings.py      # meeting CRUD, transcript upload/search
│           ├── action_items.py  # action item CRUD
│           └── search.py        # global cross-meeting search
└── frontend/
    ├── app/
    │   ├── meetings/page.tsx        # library/dashboard
    │   └── meetings/[id]/page.tsx   # transcript detail view
    ├── components/           # Navbar, Player, TranscriptPanel, etc.
    ├── lib/api.ts            # single client wrapping all backend calls
    └── types.ts              # TypeScript types mirroring backend schemas
```

**Data flow:** Next.js pages call `lib/api.ts` → FastAPI routers → SQLAlchemy
models → SQLite. All state (meetings, transcripts, summaries, action items)
persists to disk, so restarting either server doesn't lose data.

## Database Schema

- **User** 1—N **Meeting** (single seeded default user, matches "no real auth" scope)
- **Meeting** N—N **Participant** (via `meeting_participants` join table — enables filtering meetings by participant with a real SQL join)
- **Meeting** 1—N **TranscriptSegment** (speaker, start/end time, text, order)
- **Meeting** 1—N **Topic** (chapter title + timestamp, click-to-seek)
- **Meeting** 1—N **ActionItem** (text, assignee, completed flag, optional link back to the source transcript line)
- **Meeting** 1—1 **Summary** (overview paragraph)

Full column-level detail is in `backend/app/models.py`.

**Assumption:** `speaker_name` is stored as plain text on `TranscriptSegment`
rather than a foreign key to `Participant`, since real transcript exports
(VTT/JSON) typically only carry speaker labels as strings, and reliably
mapping every label to a participant record is out of scope.

## API Overview

| Method | Path | Purpose |
|---|---|---|
| GET | `/meetings` | list meetings, supports `?q=`, `?participant=`, `?sort=` |
| POST | `/meetings` | create a meeting (optionally with pasted transcript text) |
| GET | `/meetings/{id}` | full meeting detail (segments, summary, topics, action items) |
| PUT | `/meetings/{id}` | update title / participants |
| DELETE | `/meetings/{id}` | delete a meeting and all its data |
| POST | `/meetings/{id}/transcript/upload` | upload a transcript file, regenerates summary/topics/action items |
| GET | `/meetings/{id}/transcript/search?q=` | search within one meeting's transcript |
| POST | `/meetings/{id}/action-items` | add an action item |
| PUT | `/action-items/{id}` | edit / mark complete |
| DELETE | `/action-items/{id}` | delete |
| GET | `/search?q=` | global search across all meeting titles + transcripts |

Full interactive docs: `http://localhost:8000/docs` once the backend is running.

## Transcript Format

Pasted or uploaded transcripts use this format (timestamps optional):

```
[00:00:05] Alex Carter: Thanks everyone for joining.
[00:00:20] Priya Nair: Sure, let's start with design updates.
```

## Deployment

- **Backend:** Render / Railway — set start command to
  `uvicorn app.main:app --host 0.0.0.0 --port $PORT`, and run
  `python -m app.seed` once after first deploy.
- **Frontend:** Vercel — set `NEXT_PUBLIC_API_BASE` env var to your deployed
  backend URL.

## Assumptions & Placeholders

- Real-time bot, live speech-to-text, calendar/CRM integrations, team
  sharing, and real authentication are out of scope and shown as
  "Coming Soon" placeholders per the assignment.
- A single default user (`Alex Carter`) owns all meetings.
- "AI" summary/topics/action-item generation is a deterministic heuristic
  (see `backend/app/utils.py`), not a real LLM call, per assignment scope.
